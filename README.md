An enterprise-grade, coverage-first Retrieval-Augmented Generation (RAG) assistant designed for municipal government administration. Grounded strictly on official Cedarhaven municipal by-laws, service request service level agreements (SLAs), and building permit regulations.

> 🛡️ **Zero Speculation Guarantee**: The assistant never guesses or hallucinates external world knowledge. If a question is not covered by the official municipal documents, it explicitly cites what is missing and refuses speculative answers.

## 🔍 Overview & Architecture

Municipal inquiries typically cross boundaries between **By-laws**, **Permits**, and **Service Requests**. A single resident question like:
> *"Can I build a garden shed, and what are the quiet hours for construction?"*

requires simultaneous, unbiased evidence retrieval across multiple regulatory documents.

### Key Architectural Pillars

1. **Conversational Query Decomposition & Contextualization**:
   - In multi-turn dialogues, follow-up queries like *"timing"*, *"who do I call?"*, or *"can you explain in simpler bullet points?"* are contextualized against previous turns to formulate complete standalone search queries.
2. **Parallel Hybrid Retrieval (Vector + Full-Text Search)**:
   - Concurrently executes **Dense Vector Similarity Search** (`gemini-embedding-001`, 768 dimensions) and **PostgreSQL Full-Text Search** (`tsvector` + `ts_rank`) across each municipal document.
3. **Reciprocal Rank Fusion (RRF)**:
   - Normalizes and combines sparse and dense rankings with a constant ($k=60$) to eliminate raw cosine score drift across disparate document lengths.
4. **Previous Turn Citation Carry-Over**:
   - Ensures citations and evidence from the immediately preceding turn are retained in the candidate pool for seamless conversational follow-ups.
5. **Exact Citation Metadata Preservation**:
   - Page numbers are derived directly from chunk database metadata (1-indexed), **never generated by the LLM**.
   - Verified inline citations map directly to original PDF files and detected chapter/section titles.
6. **Strict Anti-Hallucination Guardrail**:
   - Out-of-scope questions (e.g., general world knowledge or municipal policies absent from the corpus) are systematically refused with a dedicated `Document Gap Notice`.

## 🚀 Quick Start Guide

### 1. Database Setup (Supabase)

1. Log in to your [Supabase Dashboard](https://supabase.com/dashboard) and create a new project.
2. Open the **SQL Editor** in the left sidebar.
3. Open [`backend/schema.sql`](file:///Users/priyanshurajput/projects/RagChatbot/backend/schema.sql) from this repository, copy its contents, and click **Run**.
4. This script sets up:
   - `pgvector` and `pg_trgm` extensions
   - `document_chunks` table with 768-dimensional vector column and `tsvector` column
   - `chat_sessions` and `chat_messages` tables
   - `match_chunks` (vector cosine similarity search) RPC function
   - `search_chunks_fts` (full-text search) RPC function
   - Public access permissions for API consumption

---

### 2. Backend Setup (FastAPI)

1. Open your terminal and navigate to the `backend` folder:
   ```bash
   cd backend
   ```

2. Create and activate a Python virtual environment:
   ```bash
   # macOS / Linux
   python3 -m venv .venv
   source .venv/bin/activate

   # Windows (Command Prompt)
   python -m venv .venv
   .venv\Scripts\activate.bat

   # Windows (PowerShell)
   .venv\Scripts\Activate.ps1
   ```

3. Install backend dependencies:
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. Configure environment variables:
   Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   Open `backend/.env` and supply your credentials:
   ```env
   # Supabase Configuration (Settings -> API in Supabase dashboard)
   SUPABASE_URL=https://your-project-id.supabase.co
   SUPABASE_SECRET_KEY=eyJhbGciOi...your-anon-or-service-role-key
   SUPABASE_PUBLISHABLE_KEY=sb_publishable_...

   # Google Gemini API Key
   GEMINI_API_KEY=your-gemini-api-key

   # Models & Tuning (defaults work out of the box)
   GEMINI_EMBED_MODEL=models/gemini-embedding-001
   GEMINI_LLM_MODEL=models/gemini-3.5-flash-lite
   EMBEDDING_DIMENSIONS=768
   ```

---

### 3. Document Ingestion

Before starting the server, run the ingestion CLI to process and index the 3 municipal PDFs into your Supabase database:

```bash
# Ensure your virtual environment is active and you are in the backend directory
python -m app.ingestion.ingest data/
```

**What the ingestion engine does:**
- Extracts text page-by-page while preserving exact 1-indexed page numbers.
- Detects section boundaries and chapter headings.
- Generates 768-dimensional dense vector embeddings with Google Gemini (`gemini-embedding-001`).
- Upserts 92 chunks idempotently into `document_chunks`.

---

### 4. Running the Backend Server

Start the FastAPI application with live hot-reloading:

## 📡 API Reference

Interactive API documentation with request builders is hosted at `http://localhost:8000/docs`.

### Core Endpoints

| Method | Route | Description |
| :--- | :--- | :--- |
| `GET` | `/health` | Live diagnostic checking Supabase connectivity, Gemini readiness, and chunk counts. |
| `POST` | `/api/chat` | Primary chat endpoint. Runs multi-document RAG and returns grounded answer with citations. |
| `POST` | `/api/sessions` | Explicitly creates a new chat session UUID. |
| `GET` | `/api/sessions/{session_id}` | Retrieves full message history and citations for a conversation session. |
| `GET` | `/api/documents` | Lists all indexed municipal documents with page counts and chunk statistics. |
| `GET` | `/api/documents/{label}/chunks` | Returns live chunk previews for the Knowledge Base modal inspector. |
| `POST` | `/api/feedback` | Records user feedback (upvote/downvote and commentary) per session. |

## 🔌 Model Context Protocol (MCP) Server

In addition to the Web UI, Wayhall exposes its entire RAG pipeline as an official **Anthropic Model Context Protocol (MCP)** server. This allows municipal officers, caseworkers, and developers to query Cedarhaven bylaws directly inside **Claude Desktop**, **Claude Code CLI**, **Telegram**, or **WhatsApp**.

### Exposed Tools
- **`ask_municipal_assistant(question)`**: Full RAG pipeline with grounded answers, 1-indexed page citations, and gap notices.
- **`search_bylaw_clauses(query, doc_filter, limit)`**: Direct hybrid vector + keyword search across raw PDF text chunks.
- **`get_municipal_corpus_summary()`**: Catalog overview of the 3 indexed documents.

### Connect with Claude Desktop
Add to your `claude_desktop_config.json` (`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS):
```json
{
  "mcpServers": {
    "wayhall-municipal": {
      "command": "/Users/priyanshurajput/projects/RagChatbot/backend/.venv/bin/python",
      "args": ["-m", "mcp_server.server"],
      "cwd": "/Users/priyanshurajput/projects/RagChatbot/backend",
      "env": {
        "PYTHONPATH": "/Users/priyanshurajput/projects/RagChatbot/backend"
      }
    }
  }
}
```

### Connect with Claude Code (CLI)
```bash
claude mcp add wayhall-assistant -- /Users/priyanshurajput/projects/RagChatbot/backend/.venv/bin/python -m mcp_server.server
```

### Connect with Telegram & WhatsApp
Complete, ready-to-use bot integration scripts are documented in [`backend/mcp_server/README.md`](file:///Users/priyanshurajput/projects/RagChatbot/backend/mcp_server/README.md).

## 🛠️ Troubleshooting & FAQs

### 1. `ResourceExhausted: 429 ... Generate content requests per day limit exceeded`
- **Cause**: Google AI Studio free-tier has distinct daily limits per model. High-demand preview models (e.g. `gemini-3.6-flash`) have lower per-day request limits.
- **Fix**: The application defaults to `models/gemini-3.5-flash-lite`, which has fast response times and generous free tier quotas. If you hit a limit, ensure `GEMINI_LLM_MODEL=models/gemini-3.5-flash-lite` in your `.env`.

### 2. `Database unreachable` in `/health`
- **Cause**: Incorrect `SUPABASE_URL` or `SUPABASE_SECRET_KEY` in `.env`.
- **Fix**: Ensure `SUPABASE_URL` starts with `https://` and points to your exact project ID (e.g. `https://xyz.supabase.co`). Ensure you ran the `backend/schema.sql` migration script in the Supabase SQL Editor.

### 3. Missing Chunks / `chunks_indexed: 0`
- **Cause**: Ingestion CLI has not been run yet.
- **Fix**: Run `python -m app.ingestion.ingest data/` from inside the `backend` folder with your virtual environment active.

### 4. CORS Errors in the Browser
- **Cause**: Frontend origin not whitelisted in backend CORS.
- **Fix**: By default, `ALLOWED_ORIGINS` in `config.py` allows `http://localhost:5173`, `http://localhost:3000`, and `*`. Verify your frontend port matches the allowed origins in `backend/.env`.
